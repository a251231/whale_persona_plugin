# 第二轮审查修复计划

- 目标：修复本轮确认的九项问题，以离线回归覆盖触发路径。
- 架构：监听器统一管理会话身份、同步和任务；Diana 管理日志格式与文件解析限制。沿用现有长期档案及会话设置存储结构。
- 技术栈：Python、LangBot SDK、httpx、unittest；不新增依赖。
- 基线与授权：AGENTS.md、两份当前 README、本轮审查结果以及用户“修复”指令。
- 兼容边界：保留群聊搭话、明确手动发布、当前会话设置、正常文件解析和联网工具；旧诊断日志缺少完整身份，隐藏而不猜测归属。
- 验证：先运行新增回归观察失败，再运行全部 unittest、compileall、git diff --check，复核 UTF-8/LF。

## 任务与检查点

1. 新增群私聊隔离、跨机器人历史/图片/群上下文、空墙只读、重置残留/竞态、后台记忆、发送路由和工具结果完整性回归，确认失败。
2. Diana：日志生产者写完整机器人/群身份，读取强制限定身份；Excel 在迭代入口限制 80 行、80 列。子智能体独立测试并实现。
3. 监听器：会话键加入机器人；整段消息处理使用同一会话锁，所有短期群缓存使用同一键；重置清除短期状态并取消关联任务；失忆防止过期记忆结果恢复。
4. 删除群提示中的私聊事实/档案；群搭话使用普通群上下文。空墙查看复用只读格式函数。
5. 日志查询限定当前群，主人私聊仅查当前机器人。后续气泡显式传递当前机器人 UUID；工具超额调用返回未执行说明，保证每个调用都有结果。
6. 同步两份 README；运行全套验证并让子智能体复审差异。

## 修复范围、退役与风险

- 根因：运行时会话身份不一致、查询调用写入函数、重置与生成及后台任务缺少共同生命周期。
- 删除旧的无机器人缓存键、群提示私聊原文、全局无权限日志查询、空墙自动发布和全表物化路径。
- 使用原有监听器作为同步和缓存唯一所有者；不新增兼容缓存或第二套命令解析。
- 会话设置及长期档案持久化键不迁移；旧日志保留在文件但不对聊天返回。
- 重要配置无需修改。回滚通过恢复本次源码、测试和文档差异；新增日志字段可由旧版本忽略。
- 架构检查：需要，覆盖缓存生产/读取/清除、群上下文数据来源、日志生产/消费、发送路由、后台记忆任务。
- 不联调真实模型和微信，不进行发布部署。历史跨机器人长期档案存储保持既有规则，本轮隔离针对短期运行时上下文。
